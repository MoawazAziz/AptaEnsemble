# AptaEnsemble — verified-data repository instructions (audit patch, 2026-10-29)

> **Status:** Research reproducibility patch for the supplied repository ZIP. This is **not yet** a final reproduction of the manuscript's Table 8 or Supplementary File 1 candidate scores. Do not describe exploratory metrics below as accepted final manuscript figures.

## Dataset

The 3,003-row `clean.csv` is a numerically unchanged, deduplicated and label-consistency-filtered subset of the AptaNet encoded dataset (`Dataset.csv`); see the independent cleaning reconstruction. Its 640 numerical predictor columns contain 340 aptamer k-mer frequencies and 300 inherited precomputed protein descriptors. The labels in the dataset are *recorded interactions* versus *unrecorded/presumed negatives*, not verified nonbinding pairs. Protein descriptors should not be described as newly generated by this project's FASTA encoder.

`M1.csv` contains 2,402 development rows, `M3.csv` contains the 601 pair-level held-out rows, and `M2.csv` is an overlapping diagnostic cohort (it overlaps M3 in 300 feature profiles and must **not** be treated as an additional independent test). The repository ZIP did not contain `train.csv` or `test.csv`; the patched main pipeline instead references `M1.csv` and `M3.csv` explicitly. The existing correction mapping under `Splits/kmer4_correction_map.csv` fixes 192 four-mer annotations without changing numerical descriptors.

## What was independently verified

- ExtraTrees 500 trees, entropy, sqrt features, balanced class weights, random state 42 on `M1.csv` gives the original **pair-level M3** metrics: accuracy 0.9501, MCC 0.8717, ROC-AUC 0.9495, recall 0.8395 with development-derived threshold 0.455.
- Independent feature-profile graph audit: 803 unique aptamer profiles, 508 protein profiles, largest bipartite connected component contains 2,879 of 3,003 edges. Both-axis disjoint evaluation of every observed pair without any excluded mixed edges is impossible under these definitions.
- Existing `Splits/cluster_disjoint_*` has **9** cosine ≥0.90 3-mer single-linkage clusters shared across train and test. This **does not** satisfy the claimed strict similarity-cluster holdout.
- Fixed 3-mer single-linkage clustering produces 718 clusters. A newly constructed `cluster_disjoint_FIXED_train.csv` (2,403 examples) / `_test.csv` (600 examples) has **zero** shared clusters, and its held-out MCC is **0.3932**, ROC-AUC **0.7558**. This is an *alternative evaluation*, not the original Table 8 endpoint.
- The released 1,324/345 doubly-disjoint train/test partition has no common identical aptamer or protein profiles but discards **1,334** cross-assignment pairs. Its new ExtraTrees model and blocked development-fold threshold yield MCC **0.1366**, ROC-AUC **0.6020**, and recall **0.3394**. These numbers **do not** reproduce the manuscript's MCC 0.1980, ROC-AUC 0.5589 and recall 0.0784.
- `doubly_disjoint_analysis.py` in the original ZIP uses ordinary stratified cross-validation for threshold selection, not doubly entity-disjoint folds. This patch instead uses a two-axis blocked development procedure, which produces predictions for 262 of 1,324 development rows; others are excluded from the eligible OOF cells.

## Candidate rankings — not certified

`candidate_ranking.py` references `train(3).csv`, `CT-20(2).txt`, `DK-30(2).txt`, `BC-6(2).txt`; these files were absent from the ZIP. Its six physicochemical group definitions and sequence-order omega=0.15 differ from the published six AptaNet-style blocks and published omega=0.05. More importantly, the encoded protein feature values in the inherited AptaNet matrix are not reproduced from FASTA by this script's function. The original model expects precisely that inherited 300-D feature space. **Do not simply change omega to 0.05 or relabel columns**: this does not guarantee numerical compatibility. Without the original sequence libraries and a verified protein encoding/preprocessing bridge, the CTGF/DKK1/BCMA priority scores cannot be honestly reproduced. `candidate_preflight.py` explicitly checks this issue and never invents candidate output.
